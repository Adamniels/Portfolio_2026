## 1. What Operation Rollout is

A **Mario Party-style party board game for 2 to 8 players, built in Unity 6 with C#**, iOS
first. Everyone plays in the same room on **their own phone**; one device hosts and the others
join with a room code over Unity Relay.

**The loop:** roll and move around a living 3D board → the space you land on fires (coins,
items, traps, map-specific effects) → when everyone has had a turn, all players drop into a
real-time **mini-game** → rewards → back to the board → repeat until the map's win condition
is met.

**The first map, Embervale**, is a medieval valley: find sacred relics, carry them back to the
castle at the centre, and be first to score the chosen number (3, 5 or 7 relics = short,
medium or long session). Relics can be stolen, dropped in an ambush, or lost when a carrier is
knocked out. The board itself changes mid-game: paths open and close, and hazards appear at
fixed round milestones (one of them, "The Kingdom Burns", plays a cutscene).

**Goal:** a finished, polished game on the App Store. Not a prototype, not a demo.

**Status (as of 2026-09-20):** in active development. The engine, board, turn loop, items,
shops, networking, session/reconnect handling and the first full map are built and working.
Mini-games and 1v1 challenges are being built out. Not released yet.

### Engineering angles worth leading with (this is what makes it portfolio-worthy)

Do not sell this as "I made a game". Sell it as **a system built to hold up**:

1. **Engine/content separation.** The core game logic assembly is *engine-free*: no
   `UnityEngine` types at all, so gameplay rules are testable as plain C#. A new board is
   data plus its own assembly that slots in behind interfaces, with zero changes to core,
   networking or presentation code.
2. **Enforced architecture.** Code compiles into layered assemblies (Core → Data → Boards →
   Network → Presentation → Rounds → Bootstrap) and a **test suite fails the build if a layer
   references upward**. Architecture is checked by CI-able tests, not by discipline.
3. **Host-authoritative networked state.** The host's simulation is the single source of
   truth; every device renders from one replicated, versioned snapshot. Late joiners and
   reconnects get current state in spawn data, and a player who drops keeps their seat.
4. **Real multiplayer edge cases handled, not hand-waved:** players going away mid-turn,
   turn skipping with a grace window, pass-and-play on one device, seat takeover on a new
   connection, rejoining after an app restart.
5. **A rule against timed guesses.** No `WaitForSeconds` standing in for "animation done" —
   animation owners expose completion signals, so tuning a duration can never desync the flow.
6. **A procedural art pipeline.** Board, arenas and props are generated from Python scripts in
   Blender into mobile-budget FBX with a single shared 256px palette texture and baked vertex
   AO — rebuildable, versioned, and tuned to a triangle budget (e.g. the valley exports at
   ~222k triangles).
7. **Built to be worked on by two people.** Mini-games live in isolated folders, assemblies
   and branches with a documented contract, so a second developer builds them in parallel
   against a stable framework.

   icons → keep `.png` with alpha. If the portfolio build has an image component
   (`next/image`, an `<Image>` wrapper, an existing `OptimizedImage`), use it and supply
   explicit `width`/`height` to avoid layout shift.
5. **Sizes:** hero ≤ 1920px wide, gallery ≤ 1400px, thumbnails ≤ 800px, icons untouched. Keep
   the full-size version only where a lightbox actually needs it.
6. **No ImageMagick on this machine.** Use macOS `sips` (see §0 for the safe pattern) or
   `cwebp` if installed, always writing into the portfolio, never into the game repo.
7. **Alt text is required and must be descriptive**, e.g. *"Low-poly medieval valley game
   board with a castle at its centre, seen from above"* — not *"game image"*.
8. **Respect existing dark/light theming.** The art is dark-petrol and warm; check that the
   images do not blow out the portfolio's light theme, and add a subtle border or container
